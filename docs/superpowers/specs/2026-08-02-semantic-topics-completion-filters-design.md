# Semantic Topics and Practice Completion Filters Design

**Date:** 2026-08-02

**Status:** Approved by the user’s explicit correction and standing instruction to proceed autonomously.

## Goal

Correct Listening and Reading Topic practice so Topic means the subject of the source content, then add consistent completed/uncompleted visibility and filtering across Listening, Reading, Writing, and Speaking.

## Correct terminology

- **Topic** means the semantic subject of a Listening Section or Reading Passage: for example Work, Travel, Education, Environment, Health, Science, Culture, Society, or History.
- **Question type** means answer mechanics such as Matching, Multiple choice, Note completion, or True/False/Not Given. It remains available to scoring, feedback, and AI Coach but is not a Topic library category.
- Listening content units are Sections 1–4. Reading content units are Passages 1–3.

## Semantic-topic architecture

The server derives one deterministic content-topic record for every Listening Section and Reading Passage from the existing OCR/source text:

```js
{
  key: "work",
  label: "Work",
  emoji: "💼",
  title: "Bankside Recruitment Agency"
}
```

Classification uses explicit content titles and weighted keyword matches. IELTS boilerplate and question instructions do not count as topic evidence. If no safe category wins, the unit is labelled `General interest`; the application does not guess a specific subject.

`/api/tasks` adds `contentTopics` maps to Listening and Reading papers without changing question text, answers, audio, pages, question-type metadata, or original paper IDs.

The Topic library becomes an alternative semantic lens over the same Section/Passage content units. A topic card contains one complete Listening Section or Reading Passage, not an arbitrary subset of same-format questions. The card shows the semantic subject and the source title. Existing question-type virtual IDs remain restorable for backward compatibility but are no longer generated by the UI.

## Filters

Listening and Reading libraries expose a compact shared filter row:

- Cambridge book;
- Test number;
- Section 1–4 or Passage 1–3 when the current scope is Sections/Passages or Topics;
- semantic Topic when the current scope is Topics;
- completion: All, Not completed, Completed.

Only books and tests present in the source bank appear. Incomplete Cambridge 1–3 materials remain excluded; the filter never manufactures unavailable books.

Writing and Speaking retain their existing source/category/search controls and add the same completion filter.

## Completion truth

An item becomes **Completed** only after a canonical scored/submitted attempt is recorded. Opening an item, starting a timer, autosaving a draft, or abandoning a session does not count.

Completion keys use stable selectable item identities:

- Listening/Reading full paper: original paper ID.
- Listening Section / Reading Passage / semantic Topic view: canonical Section/Passage ID.
- Writing: individual Task 1 or Task 2 task ID.
- Speaking: individual speaking set/topic ID.

The Topic view and Section/Passage view share the same completion key because they open the same source content. Completing a Passage through Topics therefore marks it completed in both views.

Guest completion is stored durably in the existing learning-loop history under `completedItems`. Logged-in completion is also projected from every server `practice_attempts` row, not only the latest 20 attempts. Existing local and remote attempts are migrated into the index at read time.

## Status presentation

Every selectable practice item exposes text status, not color alone:

- `✓ Completed` with the latest submission date when available;
- `○ Not completed` otherwise.

Listening/Reading unit cards show a status badge. Full-paper select labels include the status. Writing Task 1 cards and individual Task 2 question rows show it; grouped Task 2 cards show `x/y completed`. Speaking topic groups show `x/y completed`, and each selectable speaking set row has its own badge.

## Compatibility and data safety

- Same Test and Random Exam continue using only complete original papers.
- Existing source JSON, PDFs, audio, ASR cache, OCR cache, answers, and database schema are not rewritten.
- Old question-type Topic session IDs remain restorable and scorable, but new Topic navigation does not create them.
- Existing objective, Writing, and Speaking histories continue working; completion is an additive projection.
- Production deployment, environment variables, and database files remain out of scope.

## Responsive behavior

Filter controls wrap into two columns on mobile and remain at least 44px high. Status badges must not enlarge cards enough to create horizontal overflow. Desktop, iPad landscape, iPad portrait, and 390px mobile are all acceptance targets.

## Acceptance criteria

- Topic cards describe source content, never question format.
- Representative Cambridge 15 fixtures classify truthfully: recruitment as Work, holidays as Travel, eucalyptus as Environment/Nature, and Reading passages from their article subject.
- Listening can filter Sections 1–4; Reading can filter Passages 1–3.
- Both can combine Cambridge book/test, content number, semantic topic, and completion filters.
- A submitted Section/Passage is Completed in both Section/Passage and Topic views; merely opening it remains Not completed.
- Listening, Reading, Writing, and Speaking all display completion status and can filter completed/uncompleted items in their libraries.
- Guest refresh and logged-in reload preserve completion.
- Original 72 Listening and 72 Reading papers and all existing content remain unchanged.
- Existing learning-flow, ASR-caption, immersive iPad, and full-exam regressions pass.
